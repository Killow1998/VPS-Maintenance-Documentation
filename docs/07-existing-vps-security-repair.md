# 已部署 VPS 的 PHP 修复与加固

[返回目录](../README.md) · [PHP 安全更新](04-operations.md#51-容器内-php-安全更新) · [上传进度加固](04-operations.md#52-关闭不用的-php-原生上传进度)

适用于已经按本仓库部署、已有用户与订阅的 XBoard。目标是保留现有业务，仅补齐实际缺少的 PHP 修复和启动配置；不是重新安装或迁移用户。主机所有者需授权操作，真实 SSH 入口与自测订阅私下提供，不能写回本仓库。

## 1. 先判断需要修什么

每台 VPS 独立检查，不把别人的版本、容器名、路径或检查结果套到自己机器上。记录运行容器的 image ID、PHP/扩展/Octane 版本、架构、Compose project/service、数据库类型、持久卷、Redis 实际端点、INI 扫描目录、节点与 nginx 的状态。完整 inspect 和环境配置可能含秘密，仅在私有环境查看。

| 实际状态 | 处理路径 |
| --- | --- |
| PHP 不在官方修复范围、没有可信回补证据 | 按维护手册 5.1 更新运行时，然后实施 5.2；关闭上传进度不能代替升级 |
| PHP 已修复，但原生上传进度仍开启且业务不需要 | 保留原镜像，只按 5.2 增加持久 INI，重建单个面板服务 |
| PHP 已修复，上传进度关闭、cleanup 开启，但只临时改在容器可写层 | 将配置持久化并核对已有配置不会冲突；重建验证，避免下次容器替换后丢失 |
| 修复来源、启动栈或功能依赖不明 | 先补证据并说明未完成项，不盲目升级、不承诺安全 |
| 已修复且持久配置与新 worker 验证都通过 | 不重复重建；完成小型订阅、转发和计量验收并记录 |

2026-10-21 公告对应的修复版本为 PHP 8.2.35、8.3.36、8.4.27、8.5.12；执行时重新核对[PHP 官方公告](https://www.php.net/)和[两项漏洞说明](https://github.com/php/php-src/security/advisories/GHSA-6wmf-4rv5-p3rp)。发行商可能回补到旧版本号，应验证该构建的来源与回补记录，而非单看数字。不要在未知应用兼容性下跨 PHP 分支升级。

镜像拉取时间、宿主机 PHP、容器 SAPI 显示 CLI、面板只监听本机，都不能独立证明容器内 Web 运行时已修复。只拉取本仓库已发布的干净镜像也不会自动安装宿主机 INI；新应用版本更不能直接覆盖旧应用和现有数据库。

## 2. 操作顺序与停止条件

1. **准备访问和基线**：确认主机授权、可接受的面板中断窗口，以及独立 SSH/服务商控制台。若用户正在经该节点操作，解释可能中断；不保证代理无感。保存用户身份/配额、节点字段和订阅模板摘要，排除正常变化的流量、在线状态及上报时间。
2. **完成私有备份**：SQLite 用在线 backup API 并执行 `quick_check`；其他数据库使用对应一致性备份。另存 Compose、现有 INI、环境配置、节点/入口配置及实际 Redis 备份。保留确切镜像身份和可用恢复材料。无法完成备份、空间不足或无救援入口时，不开始切换。
3. **分离两个变更**：需要 PHP 更新时先走 5.1，在资源充足的外部机器限额构建和隔离验收；1 GB VPS 不编译。已修复的服务器不要为了添加 INI 重新构建。每步都独立检查，避免把应用升级、schema 迁移、规则修改捆在一起。
4. **最小配置加固**：按 5.2 安装[无凭据 INI](../templates/php-upload-progress-hardening.ini)，仅设置 `session.upload_progress.enabled=Off` 和 `session.upload_progress.cleanup=On`。保留普通文件上传、Laravel 会话驱动及原生序列化格式。若原生进度条确有依赖，先说明影响并征求方案确认。
5. **持久化、预检和回滚保护**：核对实际 INI 扫描目录，只挂载这一个文件为只读，不遮住扩展目录；已有 INI 先比较，不盲目覆盖。用精确镜像做无生产数据、无网络的受限一次性预检。审阅配置级/镜像级回滚及哈希保护，设置唯一延时任务，在切换前确认它已等待。
6. **只应用所需服务变更**：沿用原 Compose project/service、数据卷和已验证镜像，不直接用仓库参考文件覆盖运行配置。新增挂载要重建面板，不能只执行 restart；不运行安装器、不 `compose down`、不顺手重启独立节点/nginx/网络。失败按预案恢复，不不断尝试无关设置。
7. **业务验收后关闭回滚**：按下节逐项检查。通过后才停用本次 timer，确认它未执行；记录备份、镜像、INI、时间及结果。未通过时明确失败和剩余问题，不把“已准备/容器在线”写成完成。

用户 UUID、节点密钥、订阅 token、后台路径、DNS/AI/Scholar 规则、端口、额度和已有用量不在此次修改范围。正常计量会增长；不能把正常增长误认为数据被修改。不要向另一个部署复制本仓库作者的私有脚本或备份路径。

## 3. 完成标准

| 验收项 | 必须留下的私有证据 |
| --- | --- |
| 运行时 | 容器内实际 PHP 与可信修复来源；扩展/应用兼容，无新启动告警 |
| 持久配置 | INI 加载顺序、只读挂载、有效值；确认新容器/worker 已启动且没有相关覆盖 |
| 面板 | 本机面板正常；没有新增公网后台或诊断端口；中断采样与未测项有记录 |
| 订阅 | 直连真实 HTTPS 订阅返回目标客户端可解析的完整节点、DNS、组和规则，不能只测首页 |
| 转发 | 外部临时客户端明确选中目标节点，完成小型 HTTPS 请求；不只测 TCP 443 或 healthz |
| 计量与不变量 | 控制上报正常，自测流量可计量；身份、配额、订阅 URL 和模板保持不变 |
| 恢复材料 | 原配置与恢复镜像可定位；timer 已取消且未执行；普通回滚保留当前数据库/Redis |

启动配置检查命令、缺失源文件保护及只重建面板的方法直接使用[维护手册 5.2](04-operations.md#52-关闭不用的-php-原生上传进度)，不要另写一套互相矛盾的命令。PHP 升级回滚可能涉及有漏洞的旧版本，只是应急可用性恢复，必须明确尚未完成安全修复；单纯 INI 回滚不应降级 PHP。

不要公开 `phpinfo()`、原始连接或日志，也不要在生产运行 OOM/RCE PoC。无害静态端点通过不等于第三方网站登录后的所有功能通过；这不是全量漏洞审计或历史入侵取证。

## 4. 给维护 Agent 的 Prompt

把下面整段交给具备终端与 SSH 能力的 Agent。先由服务器所有者填写尖括号字段；真实信息只在私有会话中提供。Prompt 授权的是所填主机上的本次维护，不授权其他服务器或发布私有资料。

```text
请修复我已经按以下仓库部署的 XBoard，不是全新安装：
https://github.com/Killow1998/VPS-Maintenance-Documentation

先阅读 docs/07-existing-vps-security-repair.md、docs/04-operations.md 的
5.1/5.2 节、相关模板，以及目标主机已有的私有维护记录。

目标 SSH：<已有 SSH 别名，或私下提供的地址/用户/端口>。
本地私有维护目录：<目录>。
独立救援入口：<服务商控制台是否可用>。
允许的面板中断窗口：<时间范围>。
授权范围：仅这台 VPS 的 PHP 安全修复、关闭不用的原生上传进度、
必要的备份/隔离预检、单面板服务重建及验收。
范围外或新的风险需先问我；凭据、窗口缺失时先询问，不猜测。

先只读检查实际 image ID、PHP/扩展/架构、启动栈、Compose project/service、
数据卷、数据库、Redis 真实端点、INI 扫描路径及节点/nginx 状态。
重新核对官方安全公告：不要仅凭版本号、latest、宿主机 PHP 或 CLI SAPI 判断。
PHP 已修复时保留现有镜像，只补缺少的持久配置；配置已正确生效时不要重复重建。
PHP 未修复时按 5.1 选择兼容当前应用的修复镜像，候选先隔离验收，
需要编译则在经授权的外部机器限 CPU/内存/磁盘构建，不能在小 VPS 编译。
不要直接用仓库最新干净镜像替换未知的旧应用版本。

切换前完成一致性数据库、Redis 和配置备份并验证；保留确切恢复镜像。
保存身份/配额/订阅模板基线，排除正常增长的用量及上报时间。
核对业务不依赖 PHP 原生上传进度后，按 5.2 使用外置 INI：
session.upload_progress.enabled=Off
session.upload_progress.cleanup=On
仅单文件只读挂载，不替换整个 conf.d，不关闭普通文件上传，
不修改 Laravel 会话驱动或原生序列化格式；已有文件先备份比较。

预检成功后准备经审阅、有哈希保护的本机延时回滚。
只应用面板服务所需变更，沿用原 project/service 和数据卷。
不要重跑安装器、compose down、重置数据库、升级无关组件，
不要重启独立节点/nginx/网络，不动用户、额度、密钥、订阅链接或分流规则。
不保证零中断，记录实际面板不可用窗口；失败按预案回滚，不扩大修改范围。

分别验证：实际修复来源和扩展、新 worker/INI/只读挂载、面板入口，
直连真实 HTTPS 完整订阅、外部目标节点小流量转发、控制上报和自测计量。
核对身份/配额/模板未变后，才取消本次 timer 并确认未执行。
普通配置回滚保留当前已修复镜像与实时数据库/Redis，不回滚用量。

不要在生产跑利用/OOM PoC、公开 phpinfo、安装额外监控或发布凭据。
最后在私有维护目录记录日期、变更前后版本/设置、备份和回滚命令、
实际验收、失败恢复和未测项；简洁汇报是否完成、是否还需要动作。
不要假称该仓库作者已验收我的机器，不擅自推送私有资料。
```

## 5. 本指南的验收边界

该流程来源于一台既有部署的 PHP 运行时更新与后续外置 INI 加固经验；文档和模板经过结构/链接/隐私模式检查，不代表已经登录或修复其他读者的服务器。朋友的最终状态只能由其授权维护后的实际证据确认。
